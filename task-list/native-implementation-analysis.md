# ネイティブ HTML+JS+CSS 実装可能性検討

## 概要

マインドマップ Web ツールをフレームワークを使わず、ネイティブの HTML+JavaScript+CSS のみで実装する場合の可能性と課題を検討した結果をまとめる。

## 結論

**✅ 技術的には実装可能** だが、**開発効率と保守性に大きな課題**がある。

### d3.js 使用時のメリット

#### ✅ 大幅に簡単になる機能

- **マインドマップの描画**: d3.js の豊富な描画機能をそのまま利用
- **レイアウトアルゴリズム**: d3-force、d3-hierarchy などの強力なレイアウト機能
- **アニメーション**: d3 のトランジション機能で滑らかなアニメーション
- **ズーム・パン**: d3-zoom で簡単に実装
- **データバインディング**: d3 の強力なデータ駆動手法を活用

#### 📝 実装例（d3.js 使用）

```javascript
// d3.jsを使ったマインドマップ実装例
class D3MindMap {
  constructor(containerId) {
    this.svg = d3
      .select(`#${containerId}`)
      .append("svg")
      .attr("width", "100%")
      .attr("height", "100%");

    // ズーム機能の追加
    this.zoom = d3.zoom().on("zoom", (event) => {
      this.container.attr("transform", event.transform);
    });

    this.svg.call(this.zoom);
    this.container = this.svg.append("g");
  }

  drawMindMap(data) {
    // d3-hierarchyでツリー構造を作成
    const root = d3.hierarchy(data);
    const treeLayout = d3.tree().size([800, 600]);
    treeLayout(root);

    // ノードの描画
    const nodes = this.container
      .selectAll(".node")
      .data(root.descendants())
      .enter()
      .append("g")
      .attr("class", "node")
      .attr("transform", (d) => `translate(${d.x},${d.y})`);

    // リンクの描画
    const links = this.container
      .selectAll(".link")
      .data(root.links())
      .enter()
      .append("path")
      .attr("class", "link")
      .attr(
        "d",
        d3
          .linkHorizontal()
          .x((d) => d.x)
          .y((d) => d.y)
      );
  }
}
```

```javascript
// Observer Patternによる状態管理
class MindMapStore {
  constructor() {
    this.state = {
      nodes: [],
      selectedNode: null,
      canvas: { zoom: 1, x: 0, y: 0 },
    };
    this.observers = [];
  }

  subscribe(callback) {
    this.observers.push(callback);
  }

  setState(newState) {
    this.state = { ...this.state, ...newState };
    this.observers.forEach((callback) => callback(this.state));
  }
}
```

## メリット・デメリット

### ✅ メリット

- **軽量性**: フレームワークのオーバーヘッドがない
- **学習コスト**: Web 標準技術のみの知識で十分
- **依存関係**: 外部ライブラリへの依存が最小限
- **パフォーマンス**: 理論上、最適化すれば高速動作可能
- **長期保守**: Web 標準は変更されにくい

### ❌ デメリット

- **開発効率**: 開発期間が大幅に増加（3 倍程度）
- **保守性**: コードの複雑化、可読性の低下
- **再利用性**: コンポーネントの再利用が困難
- **テスト**: テストフレームワークの手動実装が必要
- **ブラウザ互換性**: クロスブラウザ対応を手動で実装
- **バグリスク**: フレームワークで解決済みの問題を再実装
- **型安全性**: TypeScript による型チェックの恩恵を受けられない
